# botmux FERRY 网关插件 1.0.0

仅限有内部 FERRY 权限的用户。本包是 Botmux 适配层，不包含上游 FERRY 实现、发布者配置或个人凭据。

## 本版修复的是实际机制

- 暂时性加速失败后，追加 **5／15／30 秒**三次重试；包括首次最多四次尝试。更长的服务端 Retry-After 优先。
- 加速线路真实返回结果后，按 Bot、话题、原生会话 ID、模型与档位保存线路偏好。工具结果接续、多轮对话和进程恢复直接优先走该线路，不每轮先回普通队列再加速。沿用旧版 24 小时有效期，成功输出续期；关闭、拒绝、手动取消或身份变化失效。
- 计时器可在没有新排队通知时唤起重试；取消、队列结束、真实输出、关闭和请求结束会撤销计时器。
- 已接入 1.0 的任务关闭加速后，不再尝试或重试；无输出的加速等待退回普通线路。已开始的回答或工具输出不被杀掉、重放。
- 辅助请求不能覆盖主任务状态，也不能取消或恢复父话题加速。
- 手动取消、临时失败、预算耗尽和拒绝冷却分别处理；自动拒绝记录过期，手动取消不自动过期。
- 控制提示不再被当作模型输出。区分“正在尝试”“已开始返回结果”“失败及下次重试”，不在上游接受前承诺成功。
- 仅有 usage/done 的空响应不算加速成功。未知输出保守禁止重放，但不据此保存成功线路；线路状态保存失败会明确提示，不能假称后续持续生效。
- 首轮未成功的话题可凭原绑定、实际主请求原生 ID 与完整回合配置安全恢复，不套用当前默认模型。
- 修复关后再开使用旧 revision、轻量状态覆盖新能力、刷新期间无法关闭和点击区域不稳定的问题。
- 恢复只读转发配置下载；端口操作必须实际启动、认证和核验，不能只保存数字。
- 管理模块使用内容寻址的实际文件名，避免 Bun 忽略 import URL 查询参数后继续运行旧模块；错误或不完整的安装明确拒绝加载。

## 开关的准确含义

**模型与档位只在 Bot 设置中选择。**总开关同时保存新话题默认值、实时加速许可和明确的旧话题换线请求。旧话题换线是异步操作，页面单独显示待空闲、切换中、已核验或待处理，不能把复选框变化当作迁移完成。Codex 加速仍以转发为前置。

| 操作 | 实际效果 |
|---|---|
| 关闭加速/总开关 | 停止 1.0 新尝试、撤销重试；无输出的加速等待退回普通线路 |
| 回答已经开始后关闭 | 当前回答不中断；等回答、工具和投递结束，再进行经验证的换线 |
| TraeX 旧话题关闭 | 创建同模型、同档位的原生可见历史副本，原话题精确接到新原生 ID；原稿不改 |
| TraeX 旧话题重新开启 | 从**当前最新历史**复制回网关，不退回关闭前的旧副本；仍不清除手动取消 |
| 关闭期间新建的原生话题 | 明确开启并验证目标历史回执后，授予该话题、目标原生 ID、模型和档位对应的加速资格；原始快照不改 |
| Codex 旧网关话题开启 | 支持本地受管 tmux：空闲后按精确原生 ID 安全休眠、无消息恢复到新网关代次；不改 provider、模型、档位或历史 |
| 旧运行代次 | 明确开启时，可在空闲边界换到已验证的新代次；在途任务和旧程序保留 |
| 休眠话题 | 复用宿主的无新消息唤醒能力，准备就绪后才换线；不注入“继续”，不重放任务 |
| 已关闭的话题 | 不擅自复活；不能把“关闭插件”变成重新执行已结束任务 |

开关不改模型、档位，不改原始历史。实际结果看旧话题换线状态及当前话题诊断，不能用默认开关或进程在线代替。
关闭后的新原生任务不探测网关健康、不因网关停服而等待；网关专用模型不能伪装成存在等价原生模型。
已有加密历史不能只改 provider。跨 provider 副本保留当前可见消息和已完成工具结果，剔除明确不可移植的加密推理状态；原稿完整保留，不总结、不重放，也不伪造成功回合。同 provider 的代次升级保留原推理项。已被原客户端压缩丢弃的内容不会凭空重建。

完整自动换线需要宿主的 `resume-target` 管理协议和 `resume-target/prepare` 无消息准备接口（上游 PR #3549）。首版自动换线支持本地受管 TraeX，活动 PTY/tmux，以及休眠 tmux；隔离、远程、adopt、自动选模、未知历史/封装明确拒绝。Codex 旧话题及没有同模型原生映射的网关专属模型，不冒充已退出原生；页面说明限制，不能偷偷换模型。宿主登记和共享服务不因一个 Bot 关闭而被卸载或停止。

Codex 的**同 provider 运行代次更新**与跨 provider 退出不同：还需宿主的
`resume-target/park` 精确空闲休眠能力。不会调用可能中断回答的普通 restart，
也不会在后台注入任务；仅在原始历史、模型、档位和当前原生 ID 都核验后更新。
恢复时使用独立的受管原生 ID 请求头，避免原生 fork 保留父缓存标识导致加速授权错配。

## 安装与升级

```bash
botmux plugin service stop gateway-acceleration
botmux plugin install @xinna/botmux-plugin-ferry-gateway@1.0.0
botmux plugin service start gateway-acceleration
```

停止的是管理服务，不是已有推理会话。不要卸载、删除 private/ 或为更新取消正在回答的任务。

默认适配精确源码哈希验证的 **FERRY 0.1.120**，保留 **0.1.98**。未知版本拒绝适配，不覆盖全局安装、不重新发布上游代码。

在管理页准备依赖并完成本人内部登录；实际进程、SDK、认证、模型目录通过后才能开启。检查版本只查元数据，更新是独立确认操作。

插件不升级 Botmux 主程序。完整正文需要 `managementLayout v1`，旧宿主从“打开设置”进入；兼容范围以实际验收记录为准。

## 状态与连接

```bash
botmux gateway:status
node "$HOME/.botmux/plugins/gateway-acceleration/dist/bin/status.mjs"
```

诊断分开显示默认设置与 currentTopic 实际状态、重试、取消、冷却和运行代次。超过两分钟的排队快照仅为历史数据。

高级设置支持：
- **下载转发配置**：使用当前已核验模型，不带登录/管理令牌或 Bot 会话头，不启用加速、不接管话题。
- **核验并切换新话题端口**：目标端口真正就绪后才提交，失败保留原线路；旧话题继续用旧端口。未来新运行代次可使用独立端口。

## 安全与验证

固定模型、档位必须匹配。自动模型池、未知封装、未核验隔离方式不自动接管。不换模型、降档、扩大上下文、关闭隔离或开启超频。鉴权/权限错误不靠自动重试绕过。原生部分工具输出也视为已生成，不因流中断重放。

程序、SDK 和数据目录按代次隔离，旧快照不重写。发布门槛包括单测、两个精确上游的原生循环隔离测试、真实浏览器鼠标/键盘/API/运行时联动，以及原生客户端和真实模型请求。DOM 变了、fixture PASS、进程在线都不是生产可用证明。

上游容量、网络与额度不是插件能消除的限制。重试不保证成功，加速不保证零排队；官方不建议无节制占用共享资源。详见 INSTALL.zh-CN.md。
